# Chain — Premium Microinteractions & Milestone Polish

Implement a focused visual-polish update for the existing **Chain Expo / React Native app**.

The app already works and its existing functionality, navigation, data persistence, Gate setup, Plan tasks, calendars, colors, notifications, and chain creation must remain unchanged.

Do **not** redesign the whole app.  
Do **not** replace working screens.  
Do **not** modify the data model unless strictly necessary.

The objective is to make the app feel more responsive, alive, premium, and native to iOS through lightweight animations, haptics, dynamic home copy, and streak milestone celebrations.

---

## 1. Reusable animated press interaction

Create or improve a reusable animated pressable component that can be applied safely to the main interactive elements.

On press-in:

- Animate scale from `1` to approximately `0.96–0.97`.
- Use a very fast, smooth response.
- Slightly reduce opacity only if it improves feedback.

On release:

- Return to scale `1` using a soft spring animation.
- Avoid exaggerated bouncing.
- The effect should feel similar to a polished native iOS control.

Apply it to:

- Primary buttons
- Chain cards
- Floating `+` button
- Color swatches
- Plan task cards
- Main Gate controls
- Modal action buttons

Do not apply it to:

- Scroll containers
- Text inputs
- Calendar day cells if it harms usability
- Native pickers
- Switches that already provide native feedback

Use the animation library already installed in the project. Prefer `react-native-reanimated` if it is already available. Do not install a large new dependency for this feature.

## 2. Improve the chain-completion interaction

When the user marks a chain as completed, add a short premium completion sequence.

The sequence should include:

1. A light or medium success haptic.
2. The completion icon/checkmark appears with a spring scale animation:
   - Start around scale `0.5`
   - Animate to approximately `1.08`
   - Settle at `1`
3. The chain card performs a very subtle bounce or pulse.
4. The completed state color fades in smoothly instead of switching instantly.
5. The displayed streak number animates when it increases.

For the streak number:

- If possible, animate the number from the previous value to the new value.
- If a full number-counter implementation risks introducing bugs, use a simpler upward slide/fade transition between the old and new value.
- Do not delay persistence or completion logic while waiting for animations.

The full interaction should last approximately `400–700 ms`.

It must feel satisfying but not childish or excessive.

Respect the system setting for reduced motion. When reduced motion is enabled, use only a short opacity transition and haptic feedback.

## 5. Streak milestone celebrations

Add a reusable full-screen or modal milestone celebration shown when a user reaches one of these streak values:

- 7 days
- 14 days
- 30 days
- 50 days
- 100 days
- 365 days

Each milestone must be shown only once per chain.

Persist which milestones have already been celebrated so reopening the app or toggling completion does not repeatedly trigger the same celebration.

Suggested structure:

- Chain logo or flame/chain symbol
- Large milestone number
- Label such as `DAY STREAK`
- Chain name
- Short motivational line
- Continue button

Example:

`30`

`DAY STREAK`

`Read 30 min`

`Consistency compounds.`

`Continue`

Visual style:

- Dark premium background consistent with the app
- Use the specific chain accent color
- Large typography with generous spacing
- Minimal soft particles, glow, or subtle confetti
- No bright multicolor party-confetti effect
- No cartoon styling

Animation sequence:

1. Background fades in.
2. Symbol/logo scales in with a restrained spring.
3. Milestone number rises or fades into place.
4. A few subtle particles appear.
5. Continue button fades in last.

Add one stronger success haptic when the milestone appears.

The animation should complete quickly, approximately `1–1.5 seconds`, and the user should be able to dismiss it immediately.

Respect reduced-motion accessibility settings.

## 6. Milestone persistence and trigger rules

Milestone celebrations must be reliable.

Trigger a milestone only when:

- The chain changes from incomplete to completed.
- Completing it causes the current streak to reach one of the milestone values.
- That specific milestone has not already been shown for that chain.

Do not trigger it:

- Every time the detail screen opens
- On every application launch
- Repeatedly after state refreshes
- When editing unrelated chain settings
- When restoring an already-completed state

Store milestone history in the existing persistence layer.

A possible model is:

```ts
celebratedMilestones: number[]
```

Add this property in a backwards-compatible way so existing chains without it default safely to an empty array.

If modifying the central model presents a high risk, create a separate persistent milestone record keyed by chain ID.
